# עוזר לנציגי שירות – ביטול, החזרים ותביעות

## מה זה

נציג מקליד שאלה חופשית ("הלקוח 4471 רוצה לבטל, מה מגיע לו?"), והכלי עונה מתוך נתוני הפוליסה ו-4 מסמכי הנהלים, עם ציטוט מקור לכל עובדה ורשימה מפורשת של מה שחסר. סכומים, תאריכים והחלטות הסלמה נקבעים בקוד בלבד. מודל השפה רק מבין את השאלה, וכותב תשובות מעוגנות ומצוטטות לשאלות כלליות על הנהלים.

## הרצה

Python 3.11+.

```bash
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
export ANTHROPIC_API_KEY=...         # אופציונלי – בלעדיו הכלי עובד במצב מילות מפתח בלבד. לעולם לא לעשות לו commit.
export ANTHROPIC_MODEL=...           # אופציונלי, ברירת מחדל claude-haiku-5-5
```

```bash
python -m insurance_assistant.cli "הלקוח 4471 רוצה לבטל, מה מגיע לו?"
python -m insurance_assistant.cli "4425 רוצה לבטל" --no-llm      # בלי מודל שפה
python -m insurance_assistant.cli "4471 רוצה לבטל" --debug       # ה-Decision המלא כ-JSON
python -m insurance_assistant.cli --report                       # דוח איכות נתונים של הייצוא
python -m insurance_assistant.cli "4471 רוצה לבטל" --as-of 2026-11-15
python -m insurance_assistant.cli                                # מצב אינטראקטיבי (שורה ריקה או Ctrl-D ליציאה)
```

`--as-of` – ברירת המחדל היא 2026-10-25, תאריך הייצוא, ולעולם לא התאריך של היום.

בדיקות והערכה:

```bash
python -m pytest -q
python -m eval.run_eval [--no-llm] [--md eval/report.md]
python -m eval.stability --runs 5          # דורש ANTHROPIC_API_KEY
```

## ארכיטקטורה

1. מילות מפתח של רגולטור נבדקות בקוד **לפני** כל קריאה למודל (`guardrails.py`); אם הן מופיעות – העברה מיידית למנהל משמרת.
2. מזהים (פוליסה, לקוח, שם, מוצר) מחולצים בקוד בלבד (`extract.py`).
3. כוונה: המודל מסווג (JSON מובנה); אם הוא לא זמין או מחזיר פלט לא תקין – גיבוי של מילות מפתח.
4. זיהוי הלקוח והפוליסה: התנגשויות, כמה לקוחות, שם עמום, כמה פוליסות – אין תשובה, אלא בקשה להבהרה (`assistant.py`).
5. בטיחות תביעות: תביעה פתוחה או לא ידועה עם כל רמז לביטול – העברה למנהל משמרת.
6. כללים דטרמיניסטיים עם ציטוט סעיף לכל עובדה (`rules/`), ואז תבנית קבועה.

כל הנתונים עוברים דרך `PolicyRepository` ו-`ValidatedPolicyRepository`: בייצור מחליפים את ה-CSV במימוש מול ה-API בלי לגעת בכללים, ו-`tests/test_repository_swap.py` מוכיח שההחלטות זהות. העיקרון: במצב מודל, מילות המפתח יכולות רק להגביר זהירות – הן לעולם לא יוצרות תשובה שהמודל לא ביקש.

- **`eval/report.md`** הוא הדוח למנהלת – התשובה של רונית ל"איך אדע שהכלי עונה נכון".

## מה לא עובד / מגבלות

- **מצב מילות מפתח בלבד** (אין מפתח, או שהמודל נכשל): מילים נרדפות לביטול (לסגור, לעזוב…) ושאלות כלליות לא מובנות. בפוליסה עם תביעה פתוחה הנציג עדיין מקבל אזהרת תביעה פתוחה, וכשמודל מוגדר נכשל מוצג באנר "מצב מוגבל".
- **הסלמת יתר מכוונת:** המילה "מפקח" לבדה (למשל "מפקח בנייה"), דגל הרגולטור של המודל, ובמצב מילות מפתח – שלילות מורכבות או "אחרי/דמי ביטול" בפוליסה עם תביעה פתוחה. הסלמה שהוחמצה היא תלונה לרגולטור; הסלמה מיותרת עולה למנהל דקה.
- **שונות של המודל:** סיווג הכוונה הוא הסתברותי. בהרצה מוקדמת, ניסוח עמום אחד ("לא שילם ורוצה לצאת") נקרא כשאלת פרטי פוליסה ב-1 מתוך 5 הרצות – נתונים אמיתיים, בלי סכומים, בלי המצאה. כלל השגיאה בבדיקת היציבות צומצם אחרי ההרצה החיה הזו, בדיוק מהסיבה הזו.
- **באג שנמצא בהרצה חיה ותוקן:** תשובות כלליות נקטעו, כי טוקני החשיבה של המודל נספרים בתוך `max_tokens`. הקריאה הכללית מקבלת עכשיו 4096 טוקנים ומגבלה של 120 מילה.
- **נתונים שאין בייצוא הפיילוט:** פרמיה ששולמה מראש, היסטוריית הקפאות, תביעות ששולמו ב-12 החודשים האחרונים, חוב שנצבר, שלב התביעה הנוכחי, תאריך היציאה בפועל לנסיעה. לכן כל הערכת ביטול מותנית ומפרטת מה חסר.
- **פרשנויות שמוצגות לנציג כהנחות:** גבולות מדרגות מענק הוותק (3 שנים בדיוק = 10%), תאריכי DD/MM, חודש חיוב = חודש קלנדרי, מועד הבקשה = תאריך השאלה, וביטול נסיעות לפני תחילת הכיסוי אינו תקופת התחרטות.
- **תשובות כלליות נבדקות למספרים ולציטוטים, לא למשמעות** – הנציג רואה את טקסט המקור המצוטט כדי לאמת. שאלה כללית יכולה לקחת עד כ-12 שניות במקרה הגרוע (timeout של 4 + 8 שניות).
- **מספרי פוליסה** מניחים 4 ספרות; 1900–2100 נקראים כשנים. `open_claims` מעל 1,000 נחשב לא תקין.

## מה הייתי עושה בייצור

- מימוש `PolicyRepository` מול ה-API של מערכת הפוליסות.
- קבלת השדות החסרים מה-API (פרמיה מראש, הקפאות, תביעות ששולמו, חוב, שלב תביעה, תאריך יציאה).
- מועד הבקשה כקלט מפורש, במקום תאריך השאלה.
- שלוש קריאות סיווג במקביל והכרעת רוב, כדי לצמצם שונות.
- לוגים וניטור.
- סט בדיקות של ביטולים אמיתיים מהעבר, עם סכומים שאושרו על ידי מחלקת הכספים.
